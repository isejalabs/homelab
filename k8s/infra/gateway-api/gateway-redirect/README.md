Separate kustomize base in order to prevent domain name rewrite errors because the `HTTPRoute` does not contain any `hostname` specification.

The route attaches to the `internal-http` Gateway (`../gateway/base/gw-internal-http.yaml`), not `internal`. The HTTP and HTTPS listeners used to live on one `internal` Gateway, but Cilium's Gateway-API-to-Envoy translation leaks every app's exact-hostname HTTPS route into the HTTP listener's own route table too, and Envoy always prefers an exact hostname match over the redirect's wildcard `*` vhost - so the redirect never fired for any hostname that had its own route (see [cilium/cilium#44123](https://github.com/cilium/cilium/issues/44123) for the related upstream bug class). Splitting the HTTP listener into its own Gateway avoids the leak; the two Gateways share one LB IP via `io.cilium/lb-ipam-sharing-key`.

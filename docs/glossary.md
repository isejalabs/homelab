# Glossary

Terms this repo uses without explaining them where they appear, one line each, alphabetical. Every entry links to the doc that owns the concept; this page only orients, the linked doc is authoritative. Entries for the 8 environments are in the same list (`dbg`, `dev`, `head`, `poc`, `prod`, `qa`, `rebuild`, `src`).

- **`base/` / `envs/<env>/` / `flux/`** — the three folders every app/infra unit under `k8s/apps/` and `k8s/infra/` has: environment-agnostic manifests, a thin per-environment overlay, and the Flux `Kustomization` that reconciles the unit. See [`architecture/kustomize.md`](architecture/kustomize.md).
- **Bootstrap** — the second of three phases of bringing up a cluster (after Terragrunt, before Flux): `helmfile` installs the foundational CRDs and infra, then hands reconciliation to Flux. See [`k8s/bootstrap/README.md`](../k8s/bootstrap/README.md#stages-of-bootstrapping).
- **Checkmk** — the monitoring system; its sites live outside the clusters and are fed by the in-cluster `checkmk-agent`. See [`architecture/monitoring.md`](architecture/monitoring.md).
- **Components layer** — the shared kustomize layer in `k8s/components/` that every environment overlay composes from (per-environment components plus transformers such as domain replacement and path rewriting). See [`k8s/components/README.md`](../k8s/components/README.md) and [`architecture/kustomize.md`](architecture/kustomize.md#the-shared-components-layer).
- **`dbg`** — environment dedicated to debugging, kept apart from `dev` so an investigation does not block feature work; runs the minimal app set. See [`architecture/environments.md`](architecture/environments.md#what-each-environment-is-for).
- **`dev`** — the primary environment for feature development, often pointed at a feature branch with `track-branch`; runs the minimal app set. See [`architecture/environments.md`](architecture/environments.md#what-each-environment-is-for).
- **Dormant environment** — one of `dbg`, `head`, `poc`, `src`, where every kopiur `SnapshotSchedule` is force-suspended (the objects stay, nothing runs on schedule). A separate grouping from the minimal/full app split. See [`kopiur-backup-restore.md`](kopiur-backup-restore.md#dormant-environments).
- **ESO (External Secrets Operator)** — syncs in-cluster secrets live from a 1Password vault; used together with `op inject` at bootstrap. See [`architecture/secrets.md`](architecture/secrets.md).
- **`fiona`** — the name of kopiur's `ClusterRepository`, which points at the S3-compatible NAS that stores the backups, with one bucket per environment. See [`kopiur-backup-restore.md`](kopiur-backup-restore.md#overview).
- **`flate`** — the tool behind the required `flate-test` CI check, which validates Flux resources across each environment's top-level sync target (`scripts/flate-test-all.sh`). See [`architecture/ci.md`](architecture/ci.md) and [`scripts/README.md`](../scripts/README.md).
- **Flux CD** — the GitOps controller that continuously reconciles `k8s/` from Git after bootstrap; checked with `flux get ks -A`. See [`architecture/overview.md`](architecture/overview.md) and [`troubleshooting-flux.md`](troubleshooting-flux.md).
- **Flux set** — a group of units registered together under `k8s/bootstrap/cluster/flux/sets/` (`infra`, `apps`, `minimal`, `soaking`); each environment's `flux/envs/<env>/` picks which sets it takes. See [`architecture/environments.md`](architecture/environments.md#1-which-apps-run-there--the-flux-minimalfull-split).
- **`head`** — the bleeding-edge environment: unreleased module tip and the newest Talos/Kubernetes versions, with the full app set, to catch breakage from new versions early. See [`architecture/environments.md`](architecture/environments.md#what-each-environment-is-for) and [`update-handling.md`](update-handling.md).
- **helmfile** — the tool the bootstrap phase uses to install CRDs and foundational infra before Flux exists. See [`k8s/bootstrap/README.md`](../k8s/bootstrap/README.md).
- **kopiur** — the Kubernetes backup operator: it snapshots PVC data to an S3-compatible repository and repopulates new PVCs from the latest backup on creation. See [`kopiur-backup-restore.md`](kopiur-backup-restore.md) and [`app-storage.md`](app-storage.md).
- **Longhorn** — in-cluster dynamic block storage, with local hourly/daily snapshots (offsite backup is kopiur's job). See [`architecture/storage.md`](architecture/storage.md#longhorn--ordinary-in-cluster-dynamic-storage) and [`longhorn-snapshots.md`](longhorn-snapshots.md).
- **Minimal / optional** — two related uses. A *minimal environment* (`dbg`, `dev`, `poc`, `src`) takes the `minimal` apps only, while a full one (`head`, `prod`, `qa`, `rebuild`) also takes the `optional` apps; all environments get the full infra set. Within `sets/apps` and `sets/infra`, `minimal/` and `optional/` are the two subfolders those sets compose. See [`architecture/environments.md`](architecture/environments.md#1-which-apps-run-there--the-flux-minimalfull-split).
- **On-demand environment** — one of `dbg`, `head`, `poc`, `src`, which may not be running at any given time; ask before starting one. The counterpart is the *standing environments*. See [`k8s-minor-upgrade.md`](k8s-minor-upgrade.md#environments-that-may-not-be-running-on-demand) and [ADR 0016](decisions/0016-identity-and-web-sso.md).
- **Pet VM** — a manually managed Proxmox VM/LXC (DNS servers, gateways, monitoring and similar) that is not Terraform-reprovisionable, so it is backed up with vzdump/PBS instead of being rebuilt from Git. See [`proxmox-backup-restore.md`](proxmox-backup-restore.md).
- **`poc`** — throwaway proof-of-concept environment for bigger, more fundamental experiments (such as swapping the GitOps controller); minimal app set and an extra standalone `vms` unit. See [`architecture/environments.md`](architecture/environments.md#what-each-environment-is-for).
- **`prod`** — production: the only 3-controlplane HA cluster, with the real (unprefixed) domain and its own pinned versions; `terragrunt apply` only from `main`. See [`architecture/environments.md`](architecture/environments.md#what-each-environment-is-for).
- **proxmox-csi** — the storage driver for volumes pinned in Terragrunt that survive a cluster rebuild. See [`architecture/storage.md`](architecture/storage.md#proxmox-csi--terragrunt-pinned-volumes-that-survive-a-cluster-rebuild).
- **`qa`** — the validation gate directly before `prod`: full app set, `terragrunt apply` only from `main`. See [`architecture/environments.md`](architecture/environments.md#what-each-environment-is-for).
- **`rebuild`** — environment that exists to rehearse cluster recovery: it is torn down and rebuilt from Git, with the full app set. See [`architecture/environments.md`](architecture/environments.md#what-each-environment-is-for) and [`disaster-recovery.md`](disaster-recovery.md).
- **Renovate / Mergify** — Renovate opens dependency-update PRs, Mergify auto-merges the eligible ones; the rules differ per environment. See [`update-handling.md`](update-handling.md).
- **sealed-secrets** — encrypts a secret so the ciphertext can be committed and decrypted only inside the cluster. See [`architecture/secrets.md`](architecture/secrets.md#sealed-secrets--for-secrets-committed-as-ciphertext).
- **Soaking** — a Flux set (`sets/soaking`) for units that are developed in `dev` and run in `qa` before they go to `prod`; `rebuild` takes it too, to rehearse the database restore. Currently Keycloak and its database. See [`architecture/environments.md`](architecture/environments.md#1-which-apps-run-there--the-flux-minimalfull-split) and [ADR 0016](decisions/0016-identity-and-web-sso.md).
- **SOPS** — age-encrypted secrets (`*.sops.yaml`) for everything that must exist before a cluster and Flux are running, chiefly Terragrunt inputs. See [`architecture/secrets.md`](architecture/secrets.md#sops-provisioning-secrets).
- **`src`** — environment for developing the `terraform-proxmox-talos` module itself, using a local checkout of it; module source changes are tested here first. See [`architecture/environments.md`](architecture/environments.md#what-each-environment-is-for).
- **Standing environment** — one of `dev`, `qa`, `prod`, `rebuild`: the environments that run units such as Keycloak, in contrast to the *on-demand environments*. See [ADR 0016](decisions/0016-identity-and-web-sso.md) (point 2) and the comment in [`sets/soaking/kustomization.yaml`](../k8s/bootstrap/cluster/flux/sets/soaking/kustomization.yaml).
- **Talos Linux** — the immutable, API-managed OS the cluster VMs run; Kubernetes is bootstrapped on it. See [`architecture/overview.md`](architecture/overview.md) and [`node-lifecycle.md`](node-lifecycle.md).
- **Terragrunt unit** — one directory `terragrunt/<non-prod|prod>/<account>/<region>/<env>/<unit>` that instantiates a module for one environment. See [`terragrunt/README.md`](../terragrunt/README.md#folder-structure).
- **`track-branch`** — a skill that temporarily points one non-prod environment's Flux instance at a feature branch to test an unmerged change live; never `prod`. See [`architecture/environments.md`](architecture/environments.md) and the [skill](../.agents/skills/track-branch/SKILL.md).
- **`vehagn-k8s`** — the Terragrunt unit that provisions an environment's Proxmox VMs and installs Talos and Kubernetes, using the `terraform-proxmox-talos` module. See [`terragrunt/README.md`](../terragrunt/README.md#cluster-vehagn-k8s).
